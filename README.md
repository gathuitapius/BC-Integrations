# BC-Integrations

A Business Central (AL) extension that connects BC with external systems in both directions:

- **Inbound:** a web shop sends orders to BC through a custom REST API. BC numbers each order automatically, creates a sales order, and posts it.
- **Outbound:** after an order is processed, BC sends the customer's details to a CRM over HTTPS. Users can also send any customer to the CRM manually from the Customer Card.

| | |
|---|---|
| Platform | Business Central, application `26.0.0.0`, runtime `15.0` |
| Object ID range | `50100`–`50149` |
| Language | AL |

---

## How it works

```
Web shop ── POST /webOrders ──▶  Web Order API (page 50120)
                                     │ 1. insert Web Sale Order (status Received)
                                     │    Order No. assigned from No. Series
                                     │ 2. Commit
                                     ▼
                              Process Web Order (codeunit 50122)
                                     │ create Sales Order (flagged "Created from BC Shop")
                                     │ post it (Ship + Invoice)
                                     │ set status = Processed
                                     │
                    ┌────────────────┴───────────────┐
                 success                           failure
                    │                                │
        Commit, then send customer          roll back sales order work,
        to CRM (silent, non-blocking)       set status = Error
```

1. The shop POSTs an order to the API page.
2. The order is saved in the **Web Sale Order** table with status **Received**. The table's `OnInsert` trigger assigns the order number from the No. Series chosen in **Web Order Setup**. The record is committed so it survives a later failure.
3. **Process Web Order** creates a sales order for the customer with one item line, copies the web order number into *External Document No.*, ticks **Created from BC Shop**, and posts it (ship and invoice).
4. On success the web order becomes **Processed**. The customer is then sent to the CRM. A CRM failure never affects the order.
5. On any failure (blocked customer, no stock, missing posting setup, and so on) the sales order work is rolled back and the web order becomes **Error**. The received order stays in the table.

## Setup

### 1. Build and publish

1. Open the folder in VS Code with the AL Language extension.
2. Check `.vscode/launch.json` points to your BC sandbox or server.
3. Run **AL: Download symbols**, then **AL: Publish** (F5).

`.alpackages/` and compiled `.app` files are not stored in the repo; they are regenerated by these steps.

### 2. Configure the number series

1. In BC, create a No. Series for web orders, for example `WEBORD`, starting at `WO-0001`.
2. Search for **Web Order Setup** and set **Order Nos.** to that series.

Without this, web order inserts fail with an error that *Order Nos.* must have a value.

### 3. Check sales posting setup

The web order process posts a real sales order, so it needs a normal working sales setup:

- The customer and the item have valid posting groups.
- Number series exist for sales orders, posted shipments, and posted invoices.
- Stock is available, unless negative inventory is allowed.

### 4. Set the CRM endpoint

The CRM URL is hard-coded in `Send Customer To CRM system` (`PostCustomer`), and currently points at a `webhook.site` test address. Replace it with your CRM endpoint. An API-key header is stubbed in a comment next to the HTTP client.

## Using the API

Base URL (standard BC API pattern):

```
https://<host>/<tenant>/api/pius/shop/v1.0/companies(<company-id>)/webOrders
```

(For on-premises, `https://<server>:<port>/<instance>/api/pius/shop/v1.0/companies(<company-id>)/webOrders`.)

The API is published as publisher `pius`, group `shop`, version `v1.0`, entity set `webOrders`.

### Fields

| JSON field | BC field | Notes |
|---|---|---|
| `id` | SystemId | Read-only |
| `orderNo` | Order No. | Read-only, assigned from the No. Series |
| `customerNo` | Customer No. | Must exist in BC |
| `itemNo` | Item No. | Must exist in BC |
| `quantity` | Quantity | Must be greater than 0 |
| `orderDate` | Order Date | Used as order and posting date |
| `status` | Status | Read-only: `Received`, `Processed`, or `Error` |

### Example: create an order

```http
POST .../webOrders
Authorization: Bearer <token>
Content-Type: application/json

{
  "customerNo": "10000",
  "itemNo": "1896-S",
  "quantity": 2,
  "orderDate": "2026-10-15"
}
```

The response contains the generated `orderNo` and the final `status`:

```json
{
  "id": "…",
  "orderNo": "WO-0001",
  "customerNo": "10000",
  "itemNo": "1896-S",
  "quantity": 2,
  "orderDate": "2026-10-15",
  "status": "Processed"
}
```

If `status` is `Error`, the order was received but the sales order could not be created or posted. Fix the cause in BC (for example, stock or posting setup) and re-submit.

### Authentication

Use whatever your environment supports for BC web services: OAuth 2.0 (Microsoft Entra) for BC online, or the authentication configured on your server for on-premises.

## Tracing orders created from the shop

Every sales document this process creates carries **Created from BC Shop = Yes**:

- Sales Order (until it is posted)
- Posted Sales Shipment
- Posted Sales Invoice

The web order number is in the sales document's **External Document No.**, so a web order can be matched to its invoice.

## Sending a customer to the CRM

**Manually:** open a Customer Card and choose **Send to CRM** (Processing). A message confirms success; failures raise an error.

**Automatically:** after a web order is posted successfully, the customer on that order is sent silently. A CRM failure is ignored, so it never undoes the order.

Payload sent as JSON:

```json
{
  "customerNo.": "10000",
  "customerName": "Adatum Corporation",
  "customerEmail": "info@adatum.com",
  "customerPhone": "555-0100"
}
```

## Known limitations

- A CRM failure on the automatic send is not logged or retried.
- The same customer is sent again on every web order; there is no "already sent" tracking.
- One web order holds one item line.
- The web order list page lets users type an order number by hand; only the API page locks it.
- Posting uses standard BC setup. An item with no stock, or a customer with no posting group, leaves the order in **Error** without storing the reason.
- The CRM URL is hard-coded.

## Ideas for next steps

- Store the error text on failed web orders.
- Store the posted invoice number on the web order and return it in the API response.
- Add a CRM setup table (URL, API key) and a "Sent to CRM" flag with retry.
- Support multiple lines per order.
